# פרויקט אחד = 7 נכסים

לפי מסמך-האב (הכרעה 6): מכל פרויקט שלם נגזרים **3 נכסי ליבה** (עוברים אישור) + **4 נגזרות** (נגזרות מהליבה המאושרת). כולם נשאבים ממסד הישויות — לא נכתבים מאפס.

## תנאי כניסה לתור התוכן
פרויקט נכנס רק אם יש לו: ‏project (עם city, domain) · ‏story **מאושר** (approved=true) · לפחות 3 media עם rights=owned · ‏project_product (אילו מוצרים). בלי story — אין תוכן; זה "הפער שאי אפשר לעקוף" (104 פרויקטים, 3 סיפורים).

## שלושת נכסי הליבה (is_core=true → תחנת האישור)

### 1. עמוד פרויקט (kind=project_page)
| חלק | נשאב מ- |
|---|---|
| כותרת: "<שם הפרויקט>, <עיר>" | project.name_norm, city |
| הבעיה | story.problem |
| מה נכשל קודם | story.prior_failure |
| הפתרון והבחירה | story.decision + project_product→product.name |
| גלריה לפני/אחרי | media (before_after, rights=owned) |
| הלקח | story.lesson |
| נתונים טכניים | product_family, trust_asset רלוונטי |
| סכמת JSON-LD | סקיל ai-seo-schema, תבנית 2 |

### 2. Case Study מקצועי (kind=case_study)
אותם שדות, פורמט PDF/עמוד להורדה, בתוספת: ציטוטים (story.quotes) · מפרט יישום מלא · שנת ביצוע + מצב היום (אם ידוע — זו הוכחת עמידות) · לוגו + פרטי קשר. קהל: אדריכלים/מפקחים — טכני, בלי סופרלטיבים. זה הנכס שנשלח בדיוור לשכבה ד'.

### 3. כרטיס מפה (kind=map_card)
תמצית ל-Heritage Map: שם + geocode (lat/lon) · שנה · סגנון (building_style) · משפט אחד מהסיפור · תמונה אחת · קישור לעמוד. ‏15 מבנים = נכס סמכות (שלב 3 בסדר הביצוע).

## ארבע הנגזרות (is_core=false — נגזרות מליבה שאושרה, לא מאושרות בנפרד)

| נכס | kind | מבנה |
|---|---|---|
| פוסט רשת | post | הוק (הבעיה) → תמונת לפני/אחרי → הלקח במשפט → קישור. עד 80 מילים |
| פריט ניוזלטר | newsletter | כותרת + 2 משפטים + תמונה + קישור. משובץ בדיוור החודשי |
| עדכון מוצר | product_update | "המוצר X בפרויקט Y" — לדף המוצר, מחזק הוכחה |
| פריט ידע | knowledge | הלקח המקצועי המנוסח כידע כללי (בלי שם לקוח) — למרכז הידע ול-Knowledge Export |

## מצבי זרימה
‏content_asset.state: ‏draft → pending_approval (ליבה בלבד) → approved → published. פרסום בפועל: סקיל wordpress-safe-ops. שיוך: כל נכס נושא project_id + domain — כך המדידה (M2, M3) יודעת לייחס הורדות ופניות לפרויקט המקור.

## סדר עבודה מומלץ
פרויקט ראשון תמיד לפי ציון: ‏audit/project-confidence-score.csv — הגבוה ביותר שיש לו story מאושר. לא מתחילים 7 נכסים לשני פרויקטים במקביל (WIP=1).
